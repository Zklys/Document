# 算法基础

## 时间复杂度分析

### 什么是时间复杂度？

简单来说时间复杂度就是一个函数，一个描述一个程序运行时长的函数。
在实际的开发过程中我们所编写的程序可能是极其复杂的，如果要找到一个函数直接得描述程序的运行时间将会十分地复杂。
于是我们一般会取对函数增长影响最大的项，将其简化后我们称之为`渐进时间复杂度`，记作：O(f(n))。

### 什么是O()？

在对于不同数据进行处理时即便是同一种算法也会有不同的时间消耗。
例如：
    - 数量：如果数据量十分的小，只有几百或者几十的数据量，那么不同的算法之间的差距不会很大。
    - 数据本身的整洁性：比如在排序算法中，如果数据本身就是已经排序完成的，那么算法能做的只有检查一遍，或者直接返回。

也就是说，在最乐观的情况下，任何算法消耗的时间都为`O(n)`，也就是随数据量的增加，线性增长。
现实中的数据往往不会如此，所以我们一般要考虑算法在最差数据的情况下所消耗的时间，即大O表示法。

>但是在工程实践中，往往不会严格的要求为最坏的情况，因为现实中也很少出现最极端的情况，所以往往认为大O表示为算法的一般情况下的时间复杂度。

### 不同数据规模的差异

在面对不同数据量的时候要选择不同的算法，这个我们之前也说过，虽然不同的算法在面对极小数据量的时候差距不会很大，但是是指在现代高性能CPU的情况下，如果面对一些性能较弱的计算机，能够减少的运算量节省性能就显得十分重要。
而且对于算法的具体实现方式也需要审查，因为在时间复杂度中，我们常常会忽略常数项和其他执行的消耗，而在小数据量的时候，这些被忽视的量也会显露出对程序执行的显著影响，

- 即：算力不足时，要通过充足的数学分析来设计程序。

### 复杂表达式的化简

之前说过，大O表示法通常只选择对函数增长率影响最大的项。

### O(logn)中的log的底

因为大O表示法是忽略常数项和其他的项，所以通过简单的数学推导就可以得到，无论log以什么为底，它们都是相等的增长率。

## 算法为什么会超时

在程序设计中我们都会偏向于使用更快的算法来压缩程序运行时间。
当然，在不同的CPU和硬件配置中相同的程序，运行所需要的时间也会有差别。

## 递归代码的时间复杂度

我们可以通过一道对x求n次方的题目来分析递归的时间复杂度。

```c
int fc(int x,int n){
    if(n==0) return 1;
    if(n==1) return x;
    int num=1;
    for(int i=n;i>0;--i){
        num *=x;
    }
    return num;
}
```

这样的代码很明显能够看出，时间复杂度为O(n)
如果我们想要让它的时间复杂度降低，就需要采用其他更高效的算法。
很自然地，我们能够想到使用递归代替循环的写法（如果你不知道，那你看到这里你就知道了）。

```c
int fc(int x, int n) {
    if (n == 0)
        return 1;
    if (n == 1)
        return x;
    return fc(x, n - 1) * x;
}
```

如果你只是简单了解过递归算法的时间复杂度的话，你可能脱口而出就是O(log n)的时间复杂度。
但是让我们来实际分析一下。
很直观地能够看出来，递归的层数就是n层，那么执行的次数就是n次，时间复杂度就是O(n)

>这个案例告诉我们，在脱口而出之前先过过脑子。

那么如何改写才能够让时间复杂度降低呢。

```c
int fc(int x, int n) {
    if (n == 1)
        return x;
    if (n == 0)
        return 1;
    int num = fc(x, n / 2);
    if (n % 2 == 1) {
        return num * num * x;
    }
    return num * num;
}
```

不难想到，我们只需要讲每次递归时的n都除以2，那么很自然的递归的深度就会为log的增长了。
所以在对于递归算法的分析时，不能盲目地指出复杂度，应该实际地分析。

## 空间复杂度分析

之前说了时间复杂度，这里就很自然地引出了空间复杂度。
如同字面意思，时间复杂度时程序运行所消耗地时间，空间复杂度就是程序运行所消耗地空间，在电脑中就是内存。
依照之前分析时间复杂度的方法，对于空间复杂度也很容易能看出来了。
就是看程序在运行中所开辟的空间的大小的变化率，取其最高次项之类的内容。
